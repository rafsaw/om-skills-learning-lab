Sequence diagrams — Human ↔ Skills ↔ Artifacts

Read every diagram the same way: what you do → what you invoke → what delegates autonomously → what artifact returns → where automation stops for you.

Interaction legend
HUMAN ACTION — you write, choose, review or approveINVOKE — you explicitly start a skillDELEGATES — autonomous skill → skill handoffARTIFACT — durable result returns✕ HUMAN GATE — automation stops for your decision
Sequence 1 · Feature path
Memory hook: human brief → invoke om-auto-write-spec → om-spec-writing creates the SPEC DOCUMENT → om-auto-write-spec continues autonomously and publishes the SPEC PR → HUMAN GATE → implementation chain.
Sequence 2 · Issue / defect path
Memory hook: om-prepare-issue prepares durable work. om-auto-fix-issue starts the autonomous bug chain: verify → root cause → fix.
Sequence 3 · PR review → runtime QA → stabilization → merge
Memory hook: review → optional runtime QA → merge-readiness automation → human ship decision → actual merge.
Sequence 4 · Runtime QA stack — shared capability
Important: om-auto-qa-pr and om-integration-tests are sibling capabilities. Both use om-prepare-test-env.
Sequence 5 · Pipeline learning loop
Memory hook: retro reports evidence and stops. A human decides whether that evidence becomes an improvement Issue and whether to execute it. Lesson 13 runtime: 10 finished PRs examined, 9 classifiable, 7 clean single-pass, 2 unexplained second-pass, 0 hard recoveries; 0% declared-outcome coverage exposed a telemetry gap. Human-approved handoff created Issue #13, but implementation was intentionally stopped at the second human gate.
